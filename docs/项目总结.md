# sql-learning-platform 项目总结

## 一、项目架构总览

```
浏览器 / Postman
      │ HTTP
      ▼
Controller 层       接收请求、参数校验、返回 Result 统一结构
      │
      ▼
Service 层          业务逻辑编排、事务控制、DTO转Entity
      │
      ▼
Mapper 层           接口定义方法（UserNativeMapper 手写、UserPlusMapper 继承BaseMapper）
      │
      ▼
Mapper XML          原生 MyBatis SQL 定义（动态SQL / ResultMap）
      │
      ▼
MyBatis 框架        预编译、参数映射、结果集映射、SQL日志
      │
      ▼
MySQL 8             执行 SQL、返回结果集
```

| 层 | 作用 | 本项目的例子 |
|---|---|---|
| Controller | 接收HTTP请求、参数绑定、返回JSON | `EmployeeController`、`AnalysisController` |
| Service | 业务逻辑、事务、参数校验、组装VO | `EmployeeServiceImpl`、`UserServiceImpl` |
| Mapper接口 | 声明数据库操作（方法签名） | `EmployeeMapper`、`SqlExecutorMapper` |
| Mapper XML | 编写真实SQL、动态SQL、ResultMap | `EmployeeMapper.xml`、`AnalysisMapper.xml` |
| Entity | 与数据库表一一对应的实体类 | `Employee`、`Orders` |
| DTO | 接收前端请求参数（不暴露实体） | `UserDTO`、`ExecuteSqlRequest` |
| VO | 返回给前端展示的视图对象 | `EmployeeVO`、`ExecuteSqlVO` |
| config | 配置类 | `MybatisConfig`（@MapperScan）、`MybatisPlusConfig`（分页插件） |

## 二、SQL 知识地图

### 1. 基础查询
- `WHERE`：行过滤
- `GROUP BY`：分组聚合，与 `聚合函数` 配合
- `HAVING`：分组后过滤（`WHERE` 过滤行，`HAVING` 过滤分组）
- `ORDER BY`：排序
- `LIMIT offset, size`：分页（全局 TopN）

### 2. 多表连接
| 连接类型 | 含义 | 案例 |
|---|---|---|
| `INNER JOIN` | 只保留两表都匹配的行 | 题1、题2 |
| `LEFT JOIN` | 保留左表全部行 | 题16（含无员工部门） |
| 自连接 | 同一张表连接两次 | 题14、15（领导关系） |
| 非等值连接 | `BETWEEN` 范围匹配 | 题3、22（薪资等级） |

### 3. 子查询
- 标量子查询：`(SELECT AVG(salary) FROM employee)` → 题22
- 表子查询：`FROM (SELECT ... GROUP BY ...) t` → 题1、2
- `ALL` 关键字：`> ALL(...)` → 题25
- `EXISTS / NOT EXISTS`：更安全的多对多判断 → 题35-1

### 4. 窗口函数（阶段6核心）
| 函数 | 用途 | 案例 |
|---|---|---|
| `ROW_NUMBER()` | 分组内唯一序号 | 分组TopN、连续问题 |
| `RANK()` | 并列排名（跳号） | 用户消费排行 |
| `DENSE_RANK()` | 并列排名（不跳号） | 面试对比 |

**连续问题通用解法**：`日期 - ROW_NUMBER()` 差值相同即连续
```sql
DATE_SUB(login_date, INTERVAL ROW_NUMBER() OVER(
    PARTITION BY user_id ORDER BY login_date) DAY) AS grp
```

**分组TopN为什么不用LIMIT**：LIMIT 只能做全局排序后截断，无法"按分类分别取前3"。
必须用窗口函数 `PARTITION BY` 分区后在分区内排序。

### 5. 行列转换
`CASE WHEN` + `COUNT/SUM` 条件聚合 → 题45 订单状态分布

## 三、MyBatis 知识地图

### 执行流程
```
Mapper接口调用
   → MyBatis 根据 namespace + methodId 找到对应的 SQL
   → 解析参数（#{} 预编译占位，${} 字符串拼接）
   → 执行 SQL（PreparedStatement 预编译，防SQL注入）
   → 结果集映射（resultType 自动映射 / resultMap 手动映射）
   → 返回 Java 对象
```

### 核心概念
| 概念 | 说明 | 本项目示例 |
|---|---|---|
| `#{}` vs `${}` | `#{}`预编译防注入；`${}`拼接用于动态表名/排序字段（有注入风险） | `SqlExecutorMapper` 用 `${sql}` 需白名单校验 |
| 动态SQL | `<if>`、`<where>`、`<set>`、`<foreach>` | `EmployeeMapper.xml` 条件查询 |
| ResultMap | 多表联查同名字段手动映射 | 员工+部门+领导三表联查 |
| 参数映射 | `@Param` 多参数、`POJO` 传参 | `EmployeeMapper.selectByCondition` |

### 分页性能（阶段6重点）
- **offset 分页缺陷**：`LIMIT 100000, 20` 数据库要先扫描并丢弃前10万行，越翻越慢
- **游标分页（seek pagination）**：记录上一页最后一条的排序字段值，用 `WHERE id > lastId ORDER BY id LIMIT 20`，走索引直接定位，O(logN)

## 四、MyBatis Plus 知识地图

### 解决的问题
- **简单 CRUD 零 SQL**：继承 `BaseMapper` 获得 `selectById/insert/updateById/deleteById`
- **条件构造器**：`LambdaQueryWrapper` 类型安全，避免魔法字符串
- **分页**：注册分页插件后 `selectPage` 自动拼 LIMIT

### 与 MyBatis 的关系
```
MyBatis Plus = MyBatis + 增强工具包
```
MyBatis Plus **底层就是 MyBatis**，完全兼容 XML 原生写法。

### 适用场景对比
| 场景 | 推荐 | 原因 |
|---|---|---|
| 单表增删改查 | MyBatis Plus | 零SQL、开发快 |
| 复杂多表查询 | 原生 MyBatis | SQL 完全可控、调优方便 |
| 报表统计/窗口函数 | 原生 MyBatis | 需手写复杂SQL |
| 分页查询 | 均可 | Plus 自动、Native 手写 |

### 代码量对比（阶段7 `/api/users/compare`）
- 原生 MyBatis：接口声明 7 个方法 + XML 手写 7 段 SQL
- MyBatis Plus：继承 BaseMapper，0 方法 0 SQL

## 五、慢 SQL 分析与优化（阶段6）

### EXPLAIN 关键字段
| 字段 | 含义 | 优化目标 |
|---|---|---|
| `type` | 访问类型：ALL(full scan) < index < range < ref < const | 避免 ALL |
| `key` | 实际使用的索引 | 优先走覆盖索引 |
| `rows` | 预估扫描行数 | 越小越好 |
| `Extra` | Using filesort / Using temporary | 尽量避免 |

### 索引失效场景（本项目可练习）
1. **where 字段计算**：`WHERE salary * 12 > 60000` → 应改为 `WHERE salary > 60000/12`
2. **隐式类型转换**：字符串列 `WHERE phone = 13800000001`（数值）→ 索引失效，应传字符串
3. **like 前缀模糊**：`LIKE '%张%'` 无法走索引，只有 `LIKE '张%'` 可走
4. **OR 条件**：`WHERE name = 'a' OR phone = 'b'` 可能全表扫描，改 UNION 或用覆盖索引

### 联合索引最左前缀
`(dept_id, salary)` 联合索引：
- `WHERE dept_id = ? AND salary > ?` ✅ 走索引
- `WHERE salary > ?` ❌ 跳过了最左列 dept_id，索引失效

## 六、AI 代码审查清单

拿到 AI 生成的 Java 后端代码，按以下顺序审查：

1. **SQL 合理性**
   - [ ] 是否 SELECT 了不需要的列（避免 `SELECT *`）
   - [ ] WHERE 是否使用了索引、有没有索引失效
   - [ ] 多表查询 JOIN 是否合理，有没有笛卡尔积
   - [ ] 分页是否用了深 offset（大数据量应游标分页）
   - [ ] 聚合是否会用错 HAVING/WHERE

2. **MyBatis 设计**
   - [ ] 动态 SQL 是否写对（`<if>` 条件、`<where>` 前缀）
   - [ ] `#{}` vs `${}` 是否安全（禁止随意拼接不可信输入）
   - [ ] ResultMap 字段映射是否完整
   - [ ] 批量操作是否用 `<foreach>` + 避免循环单条SQL

3. **三层结构**
   - [ ] Controller 是否只做参数接收和返回，无业务逻辑
   - [ ] Service 是否有事务注解 `@Transactional`（写操作）
   - [ ] 是否直接用 Entity 接收请求（应使用 DTO）
   - [ ] 异常是否被统一处理，是否泄露了 SQL 细节

## 七、面试高频题总结

### SQL 面试题
| 题目 | 一句话答案 |
|---|---|
| 窗口函数有哪几种？ | ROW_NUMBER 不并列、RANK 并列跳号、DENSE_RANK 并列不跳号 |
| 连续登录N天怎么做？ | 日期减ROW_NUMBER，差值相同即连续，再 GROUP BY |
| 分组TopN为什么不用LIMIT？ | LIMIT不能分区，窗口函数 PARTITION BY 分区内排序 |
| WHERE和HAVING区别？ | WHERE过滤行（分组前），HAVING过滤分组（分组后） |
| EXISTS和IN区别？ | EXISTS提前短路且对NULL安全，大表更推荐EXISTS |

### MyBatis 面试题
| 题目 | 一句话答案 |
|---|---|
| `#{}`和`${}`区别？ | `#{}`预编译占位防注入，`${}`字符串拼接有注入风险 |
| 一二级缓存区别？ | 一级缓存SqlSession级默认开启，二级缓存Mapper级需开启 |
| 什么时候动态SQL？ | 条件不固定时用 if/where/foreach |
| MyBatis执行流程？ | 加载配置→SqlSessionFactory→SqlSession→Executor→MappedStatement→执行→映射 |

### MyBatis Plus 面试题
| 题目 | 一句话答案 |
|---|---|
| MyBatis和MyBatis Plus关系？ | Plus基于MyBatis增强，简单CRUD零SQL |
| 什么时候用Plus什么时候用MyBatis？ | 简单CRUD用Plus，复杂查询/报表用MyBatis手写XML |
| Wrapper是什么？ | 条件构造器，LambdaQueryWrapper类型安全无魔法字符串 |

## 八、快速开始

### 1. 初始化项目（从零开始）

```bash
# ① 先改数据库账号密码（默认 root/root1234）
vim src/main/resources/application.yml
#    datasource.username / datasource.password 改成你本机 MySQL 的账号密码

# ② 启动应用（自动完成：建库 → 建16张表 → 初始化数据 → 写入22道SQL题目）
mvn spring-boot:run

# ③ 访问 SQL 实验中心页面
open http://localhost:8080
```

启动日志看到这两行即代表初始化成功：
```
Started SpringMybatisSqlApplication in 1.075 seconds
SQL 实验中心：成功初始化 22 道题目
```

> 幂等说明：schema.sql 用 `CREATE TABLE IF NOT EXISTS`、data.sql 用 `INSERT IGNORE`，
> 重启应用不会重复建表/插数据，不会报错。

### 2. 如何继续添加 SQL 题目（重点）

题目都维护在 `SqlCaseInitializer.buildCases()` 方法中（`src/main/java/com/dev/springmybatissql/config/SqlCaseInitializer.java`）。

**新增一道题的步骤：**

```java
// 在 buildCases() 方法 return list 之前，追加一条：
list.add(caseOf(
    50L,                      // ① id：不能与现有题目重复（现有 1~46）
    "每个部门薪资第二高的员工（自定义题）",   // ② 标题
    "【数据模型】employee、department\n【SQL分析】...\n【核心知识】...\n【面试表达】...", // ③ 题目描述
    "进阶",                   // ④ 难度：入门/进阶/困难
    "窗口函数/dense_rank",    // ⑤ 核心知识点(标签)
    "SELECT ... FROM ..."     // ⑥ 标准SQL答案（启动时自动执行，生成 expected_result）
));
```

**验证：**
- 重启应用，看到 `SQL 实验中心：成功初始化 N 道题目`（N=22+新增数）
- 或手动清空后重启（清空才会重新生成 expected_result）：
  ```sql
  DELETE FROM sql_case;
  ```

**注意：**
- 标准SQL必须能以当前数据库数据跑通（启动时真实执行生成 expected_result）
- 若 SQL 写错，启动日志会打印 `初始化题目失败 id=xx`，修正后 `DELETE FROM sql_case` 再重启即可
- 题目 id 建议跳号预留（如 50L），方便以后插入/重排
