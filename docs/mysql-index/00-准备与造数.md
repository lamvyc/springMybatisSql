# 阶段 0：准备 —— 建表 + 造数

> 目标：造出“量足够大、能明显看出索引差别”的三张真实业务表。
> 预计耗时：10 分钟（100 万订单生成约 1~3 分钟，视机器而定）。

## 0.1 为什么单独建一套 mall_* 表

本工程的原有表（`user/orders/product` 等）只有几十行，是给 SQL 实验台 35 题用的。
索引学习需要 **数据量大到能真实影响查询性能**，所以新建独立业务表，前缀 `mall_`
与原有表完全隔离：

| 表              | 行数(默认) | 模拟业务                                                            |
|----------------|--------|-----------------------------------------------------------------|
| `mall_user`    | 30 万   | 商城注册用户（用户名唯一、手机号随机、状态 98% 正常）                                   |
| `mall_product` | 20 万   | 商品（200 个分类，分类37 上架约 847 个，用于回表演示）                               |
| `mall_order`   | 100 万  | 订单（状态分布贴近真实：已支付 50%；80% 订单集中在 10% 活跃用户；时间散布在 2023-01 ~ 2024-12） |

**造表时刻意只保留两类索引：**

```sql
PRIMARY KEY (id)              -- 主键索引（InnoDB 聚簇索引，天然存在）
UNIQUE KEY uk_username (...)  -- 业务唯一索引（用户名/订单号天生不能重复）
```

> 为什么不把 phone/status/create_time 的索引一开始就建好？
> 因为教程要从“没有索引”的状态开始，让你亲眼看到 MySQL 是怎么全表扫描的。
> 先忍住，等阶段 1~3 亲手 `CREATE INDEX`。

## 0.2 执行建表 + 造数

```bash
# 确保应用跑过一次（数据库 sql_learning_platform 已存在）后执行：
mysql -h127.0.0.1 -uroot -proot1234 sql_learning_platform \
  < docs/mysql-index/sql/00_建表与造数.sql
```

脚本顶部可以改规模（默认值已注释）：

```sql
SET @USER_N    = 300000;   -- 用户行数
SET @PRODUCT_N = 200000;   -- 商品行数
SET @ORDER_N   = 1000000;  -- 订单行数
```

> ⚠️ 本文件是“一键重置”：会 DROP 重建 mall_* 三张表并重新造数。
> 想保留当前造的 100 万行、只清索引，用各阶段脚本开头自带的“幂等重置”段即可。

## 0.3 预期输出（真实执行结果）

```
+-------------+---------+
| 表名         | 行数     |
+-------------+---------+
| mall_user   |  300000 |
| mall_product|  200000 |
| mall_order  | 1000000 |
+-------------+---------+
```

`SHOW INDEX` 应只看到主键与业务唯一索引（**没有**任何二级索引）：

```
mall_user   : PRIMARY, uk_username
mall_product: PRIMARY
mall_order  : PRIMARY, uk_order_no
```

脚本末尾还执行了 `ANALYZE TABLE`。这一步很容易被忽略但**很重要**：
大批量插入后优化器手里的“索引基数”是旧的，不 ANALYZE 会导致后面
EXPLAIN 预估的 `rows` 严重失真（真实项目里常见的坑）。

## 0.4 做 3 个小验证，确认数据像“真实业务”

```sql
-- ① 一个用户的订单构成（应该有多个状态，教程阶段3用 user_id=29997 举例）
SELECT user_id, status, COUNT(*) FROM mall_order WHERE user_id = 29997 GROUP BY status;

-- ② 状态分布（已支付占比最高，模拟真实订单）
SELECT status, COUNT(*) FROM mall_order GROUP BY status;

-- ③ 分类 37 的上架商品数（阶段4 用 category_id=37）
SELECT COUNT(*) FROM mall_product WHERE category_id = 37 AND status = 1;
```

## 0.5 记住的 3 件事

1. 教程所有 SQL 跑在同一个库 `sql_learning_platform`，表前缀 `mall_` 保证不干扰原项目。
2. 想让查询“变回最慢的样子”，重新执行阶段脚本顶部的幂等重置即可（不删数据）。
3. 拿到一个真实手机号备用（下面每阶段都要用到）：
